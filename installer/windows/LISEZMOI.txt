AVAStack — Live stacking
========================

Merci d'avoir installé AVAStack !

LANCEMENT
---------
Double-clique sur le raccourci "AVAStack" (Bureau ou Menu Démarrer),
ou sur lancer_avastack.bat dans ce dossier.

SUPPORT DES CAMÉRAS
-------------------
AVAStack gère plusieurs marques de caméras. Les SDK constructeurs sont
INCLUS dans ce dossier d'installation :

✅ INCLUS (aucune action) :
  - QHYCCD  : le SDK est embarqué dans l'installation (paquet qhyccd).
              Branche simplement ta caméra, choisis "QHY (SDK)" dans
              l'application, et c'est parti.
  - ZWO ASI : ASICamera2.dll est installée dans CE dossier (et le paquet
              zwoasi est installé dans le venv).
  - Player One : PlayerOneCamera.dll est installée dans CE dossier.
  - Touptek / Altair : ToupCam.dll est installée dans CE dossier
              (fonctionne aussi pour les clones : Altair et autres
              marques revendant l'électronique ToupCam).
  - SVBONY : SVBCameraSDK.dll est installée dans CE dossier.
  - Simulée : ciel de démo, sans matériel.
  - Dossier surveillé : empile les FITS/PNG/TIFF que ton logiciel
              d'acquisition (N.I.N.A., APT, SharpCap...) écrit dans un dossier.
  - OpenCV : webcams / cartes d'acquisition génériques.

REMARQUE : si tu dois remplacer une DLL par une version plus récente,
copie-la simplement dans CE dossier (ou définis une variable
d'environnement pointant vers le dossier qui la contient, par exemple
AVASTACK_PLAYERONE_DIR=C:\chemin\vers\SDK\PlayerOne).

CATALOGUES (ASTRONOMÉTRIE ET COULEURS)
--------------------------------------
L'astrométrie (et la photométrie/couleurs qui en dépendent) s'appuie sur les
DONNÉES Gaia DR3 de Siril — des FICHIERS d'étoiles, pas des DLL. Une ligne
« Catalogues », dans la fenêtre « Astrométrie », dit à tout moment :

  - OÙ l'application cherche (dossier utilisé) ;
  - si le catalogue astro est PRÉSENT ou ABSENT ;
  - combien de morceaux « spectres Gaia » (utiles à la SPCC) sont installés.

Elle est accompagnée de deux boutons :

  - 📂 : choisir un AUTRE dossier de catalogues (le choix est mémorisé) ;
  - ⬇ Gaia : télécharger le catalogue astrométrique (≈ 1,1 Go) dans ce dossier
    — reprise automatique si la connexion coupe, empreinte sha256 vérifiée.

Ordre de recherche (le premier utilisable gagne) : le dossier choisi par 📂,
puis %LOCALAPPDATA%\Siril (celui de Siril), puis un dossier « catalogues »
dans %APPDATA%\AVAStack — c'est là qu'écrit le bouton ⬇ si rien d'autre
n'existe. Sans catalogue, l'astrométrie le DIT (« DONNÉES MANQUANTES — … »)
au lieu d'échouer sans explication.

Autre possibilité : ASTAP (astap_cli + une base d'étoiles de type G18/H18
pour chercher sans coordonnées) — AVAStack le détecte dans le PATH, dans
« C:\Program Files\astap » et dans les emplacements Linux/macOS.

BANCS CAMÉRA INSTALLÉS (sous-dossier bancs\cameras)
--------------------------------------------------
Les outils autonomes de diagnostic caméra sont installés avec AVAStack, dans
le sous-dossier bancs\cameras :
  - _diag_camera_qhy.py        (caméras QHY / QHYCCD)
  - _diag_camera_playerone.py  (caméras Player One, ex. Uranus-C Pro)
  - _diag_camera_svbony.py     (caméras SVBONY, ex. SV305C de guidage)
  - _diag_camera_touptek.py    (caméras Touptek/Altair et clones ToupCam)
  - _diag_qhy_sdk.py           (le SDK QHYCCD seul, sans caméra branchée)

Ils réutilisent le MÊME code caméra que l'application, mais hors
application : idéal pour comprendre un problème de caméra sans toucher au
live stacking. Ce sous-dossier ne contient QUE ces outils : les bancs de
régression de la couche caméra (_test_camera_*.py, _test_capacites*.py,
_test_tec*.py…) tournent à vide (SDK factices), sans jamais voir tes
pilotes ni tes caméras : ce sont des outils de développement, ils restent
dans le dépôt.

Pour en lancer un :
  1. ouvre une invite de commandes dans ce dossier ;
  2. tape :  venv\Scripts\python.exe bancs\cameras\_diag_camera_playerone.py
     (ou      venv\Scripts\python.exe bancs\cameras\_diag_camera_svbony.py
      ou      venv\Scripts\python.exe bancs\cameras\_diag_camera_qhy.py
      ou      venv\Scripts\python.exe bancs\cameras\_diag_camera_touptek.py)

⚠ UN SEUL programme à la fois peut ouvrir une caméra : fermer le banc
  avant de lancer AVAStack, et inversement.

Les AUTRES bancs (solveur, couleurs, chromatisme, sauvegardes, gradient,
alignement… ET les bancs de régression caméra _test_*.py) ne sont PAS
installés : ce sont des outils de développement. Ils vivent dans le dépôt du
projet, sous bancs\, et se lancent depuis la racine du dépôt avec
l'environnement Python du dépôt.

Le banc PLAYER ONE permet de :
  - DÉTECTER les caméras Player One et lire leur fiche (modèle, capteur,
    couleur/mono, taille, bins supportés, formats, TEC, USB3, ST4) ;
  - OUVRIR la caméra et ÉNUMÉRER AUTOMATIQUEMENT tous ses contrôles
    (attributs min/max/défaut + valeur courante) ;
  - afficher un VERDICT « possibilités » : plages d'exposition, de gain
    (avec le gain unitaire du capteur quand il est connu), d'offset,
    refroidissement TEC, binning, ROI, formats ;
  - RÉGLER en direct : exposition (µs), gain, offset, TEC (consigne +
    arrêt + lecture °C et % de puissance), binning, ROI, format, flip,
    bande passante USB ;
  - AFFICHER le flux live avec les fps réels ;
  - enregistrer un RAPPORT complet dans %TEMP% (bouton « 💾 Sauver le
    rapport »).
  Mode console (détection rapide, sans fenêtre) :
     venv\Scripts\python.exe bancs\cameras\_diag_camera_playerone.py --console

  ⚠ Le banc réutilise la sonde de l'application : si les fichiers
    avastack\cameras\playerone.py et avastack\cameras\capacites.py
    installés sont ANTÉRIEURS à la version du banc, celui-ci le signale
    (bandeau rouge) au lieu de planter — réinstalle alors la version
    courante d'AVAStack.

Le banc SVBONY permet de (ex. SV305C de guidage) :
  - DÉTECTER les caméras SVBONY (version du SDK, fiche : nom, n° série,
    taille, couleur/mono, bits, Bayer, bins supportés, formats) ;
  - OUVRIR la caméra (SVBOpenCamera — pas d'init séparée dans ce SDK) et
    ÉNUMÉRER AUTOMATIQUEMENT tous ses contrôles via la sonde de
    l'application (SVBGetNumOfControls + SVBGetControlCaps + valeur
    courante) ;
  - afficher un VERDICT « possibilités » : plages exposition / gain /
    BlackLevel (« offset » SVBONY), TEC éventuel, bins, ROI, formats ;
  - RÉGLER en direct : exposition (µs), gain, BlackLevel, TEC (⚠ les
    températures SVBONY sont en unités de 0,1 °C — le banc convertit),
    bin (via SVBSetROIFormat : taille FINALE après bin), format
    (RAW8/RAW16/RGB24…), flip (UN seul contrôle 0-3) ;
  - AFFICHER le flux live avec les fps réels ;
  - enregistrer un RAPPORT complet dans %TEMP%.
  Mode console : venv\Scripts\python.exe bancs\cameras\_diag_camera_svbony.py --console
  ⚠ Même contrôle de version que le banc Player One : si
    avastack\cameras\svbony.py ou avastack\cameras\capacites.py sont
    antérieurs au banc, celui-ci le signale (bandeau rouge) au lieu de
    planter.

Le banc TOUPTEK permet de (Touptek/Altair et clones ToupCam) :
  - DÉTECTER les caméras branchées via l'API MODERNE (Toupcam_EnumV2) et
    lire leur fiche : nom, id opaque, drapeaux (mono/couleur, TEC, USB3,
    ST4, RAW 10/12/14/16, ventilateur, roue à filtres...), taille de pixel,
    résolutions live et pose, nombre de vitesses ;
  - OUVRIR la caméra (Toupcam_Open sur l'ID opaque) en mode RGB24
    (débayerisation par la caméra, comme dans l'appli) et MESURER sur la
    caméra elle-même : plages d'exposition (µs) et de gain (% — 100 = 1x),
    exposition RÉELLE, vitesse, niveau de noir, TEC (allumé/éteint,
    consigne en 0,1 °C, température capteur), ventilateur ;
  - ÉPROUVER la plage du NIVEAU DE NOIR : le SDK n'a AUCUNE fonction de
    plage pour cette option — le banc affiche le PLAFOND déduit de l'entête
    officiel (TOUPCAM_BLACKLEVELn_MAX = 31 × 2^(n-8), n = profondeur de
    bits annoncée) puis MESURE la borne réelle par DICHOTOMIE posé/relu
    (fonction de l'application, valeur d'origine restaurée). CONSTAT
    G3M662M : la caméra annonce 16 bits mais refuse 7936 et accepte 31 →
    plage réelle 0 → 31, le verdict affiche la plage CONSTATÉE ;
  - RÉGLER en direct : exposition (µs), gain (%), noir, TEC (consigne °C,
    marche/arrêt via les OPTIONS TECTARGET 0x0f et TEC 0x08 — la DLL n'a
    PAS de CoolerOn), résolution (put_eSize), binning MATÉRIEL
    (Average/Add/Skip), ROI (départ + taille, PAIRES, min 8×8) ;
  - AFFICHER le flux live (flux ÉVÉNEMENTIEL : le SDK pousse les frames via
    un callback — les fps viennent aussi de Toupcam_get_FrameRate) ;
  - DÉCLENCHER une pose (Toupcam_Snap → événement STILLIMAGE) ;
  - afficher un VERDICT « possibilités » + identité complète (n° série,
    versions firmware/hardware/FPGA, date de production, révision,
    formats de pixel supportés, binning supporté) ;
  - enregistrer un RAPPORT complet dans %TEMP%.
  Mode console : venv\Scripts\python.exe bancs\cameras\_diag_camera_touptek.py --console
  ⚠ Même contrôle de version que les autres bancs : si
    avastack\cameras\touptek.py installée est ANTÉRIEURE à la correction
    API V2 (≥ 2.21.8), à la table de plage du niveau de noir du
    jalon 50 (≥ 2.21.9) ou à la mesure du noir + TEC pilotable du
    jalon 51 (≥ 2.21.10), le banc le signale (bandeau rouge) au lieu de
    planter.

Le banc QHY permet de :
  - DÉTECTER les caméras QHY branchées ;
  - OUVRIR la caméra selon deux séquences (celle de l'application, et une
    pas-à-pas où chaque étape est tracée) ;
  - IMPOSER une ROI (zone de lecture) avant le démarrage du flux ;
  - AFFICHER le flux live, avec les fps et la taille réelle du capteur ;
  - LISTER tous les contrôles du SDK avec leur nom officiel et leur
    valeur (gain, offset, exposition, USB traffic, température...) ;
  - ÉCRIRE n'importe quel contrôle (set_param) ;
  - PILOTER LE REFROIDISSEMENT : consigne de température (régulation
    automatique) ou puissance TEC manuelle, avec lecture de la
    température du capteur et du PWM courant.
    ATTENTION : la MiniCam8M est une caméra REFROIDIE — il lui faut son
    alimentation 12 V pour que la régulation fonctionne (et pour que la
    température lue ait un sens) ;
  - SONDE CTYPES NATIVE (boutons "Plages (MinMaxStep)", "Tourner
    (ctypes)", "Statut CFW") : appelle la DLL QHYCCD directement, sans
    le paquet Python — lit les PLAGES réelles de tous les contrôles
    (min/max/pas : exposition, gain, offset, TEC...) et pilote la ROUE
    à filtres intégrée (détecter, lire la position, tourner avec
    confirmation). La sonde s'exécute en tâche séparée, refuse de
    tourner pendant que le flux est actif, et affiche le chemin exact
    de la DLL utilisée.

En cas de fermeture brutale de la fenêtre sans message (crash natif du
SDK), le bouton "Ouvrir le log" — ou le fichier avastack_qhy_debug.log du
dossier temporaire — indique la DERNIÈRE étape réussie : c'est elle qu'il
faut me transmettre.

TRAITEMENT EXTERNE (optionnel)
-----------------------------
GraXpert et BlurXTerminator (rc-astro.exe) ne sont PAS fournis : ils
s'installent à part. AVAStack les détecte (chemin noté par Siril, variable
AVASTACK_GRAXPERT / AVASTACK_RC_ASTRO, PATH, dossiers d'installation
courants) et AFFICHE toujours le résultat : une ligne d'état sous chaque
commande du cadre "Traitement externe (long)" dit
    ✔ GraXpert : C:\...\GraXpert.exe                (vert)
    ⚠ GraXpert : exécutable introuvable...          (orange)
Si la ligne est orange, désigne l'exécutable avec le bouton "…" : le
chemin est mémorisé. Un traitement externe dont l'outil est introuvable
n'est plus lancé du tout : tu es prévenu AVANT, au lieu de voir échouer la
chaîne après plusieurs minutes.

RÉGLAGES DE BXT (important) : le CLI rc-astro applique SES PROPRES
valeurs par défaut tant qu'on ne passe rien — dont 0,50 pour
l'accentuation des OBJETS (--sn), qui ajoute un moucheté de couleur dans
le fond du ciel (mesuré ×1,28 contre la vue live sur un empilement réel).
La commande fournie passe désormais les paramètres EXPLICITEMENT :
  --ss 0.5 (étoiles)  --ash -0.3 (halos)  --sn 0.3 (objets)
Si ta commande mémorisée date d'avant, ajoute simplement " --sn 0.3 " à
la fin du champ : le fond devient nettement plus lisse (moucheté mesuré
divisé par 2,7). Ces paramètres sont écrits dans l'en-tête des fichiers
enregistrés (mots-clés AVACMDBX, AVACMDGX, AVAOUTIL) : tu peux donc
vérifier après coup ce qui a réellement été appliqué.
