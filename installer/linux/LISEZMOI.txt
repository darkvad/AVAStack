AVAStack — live stacking : LISEZ-MOI LINUX
==========================================

Merci d'avoir installé AVAStack ! Ce fichier concerne l'installation sous
Linux (le paquet est `avastack-setup-<version>-linux.tar.gz`).

CE QUI FONCTIONNE DANS CETTE VERSION
------------------------------------
Les sources d'images « sans caméra » sont prêtes et opérationnelles :
  - Simulée (démo)             : ciel de démonstration, sans matériel ;
  - Dossier surveillé          : empile les FITS/PNG/TIFF que ton logiciel
                                 d'acquisition (N.I.N.A., KStars/Ekos,
                                 APT, SGP...) écrit dans un dossier ;
  - Composition multi-dossiers : RGB / HOO / SHO / LRGB (une couche par
                                 dossier) ;
  - OpenCV 0 et 1              : webcams et cartes d'acquisition génériques
                                 (périphériques /dev/video0, /dev/video1).
Tout le traitement est là : calibration (dark/flat), alignement, empilement
avec rejet, étirement VeraLux, histogramme, sauvegardes FITS/TIFF/PNG,
astrométrie, photométrie, outils externes (GraXpert / BlurXTerminator).

CAMÉRAS : PAS ENCORE INSTALLÉES (c'est volontaire)
--------------------------------------------------
Les caméras astronomiques (QHY, ZWO, Player One, Touptek, SVBONY) ont besoin
d'un SDK binaire fourni par le constructeur — sous Linux ce sont des
fichiers `lib*.so` (plus les règles udev), et NON des paquets pip. Ce paquet
n'en embarque aucun : l'application démarre sans eux, et l'ouverture d'une
source caméra se contentera de dire que le SDK est introuvable.

Quand tu auras récupéré les bibliothèques constructeurs, dépose-les dans le
dossier EXTRAIT du paquet (à côté de `AVAStack.py`, ou dans un sous-dossier
`sdk/`), puis relance l'installateur depuis ce dossier :

    bash installer/install_avastack.sh --cameras

Il installe alors les paquets caméras (qhyccd, zwoasi) et copie les
`*.so` présents. Les règles udev (`*.rules`) seront posées dans
/lib/udev/rules.d par l'installateur (avec sudo) : sans elles, la caméra
n'est visible QUE en root.

(Tu peux aussi pointer un dossier existant avec la variable d'environnement
AVASTACK_<MARQUE>_DIR, par exemple AVASTACK_PLAYERONE_DIR=~/SDK/PlayerOne.)

  - QHY      : rien à télécharger (le paquet pip qhyccd embarque le SDK).
  - ZWO      : libASICamera2.so + asi.rules.
  - Player One : libPlayerOneCamera.so + ses règles, et libusb-1.0-0.
  - Touptek/Altair : libtoupcam.so + ses règles.
  - SVBONY   : libSVBCameraSDK.so + ses règles.

ASTRONOMÉTRIE : IL FAUT UN CATALOGUE D'ÉTOILES
---------------------------------------------
L'astrométrie (et la photométrie/couleurs qui s'appuient dessus) a besoin des
DONNÉES Gaia DR3 de Siril — ce ne sont pas des bibliothèques (*.so), ce sont
des FICHIERS d'étoiles, et ils ne sont pas fournis dans ce paquet :

  - soit tu les as déjà (Siril installé) : AVAStack cherche dans
    ~/.local/share/siril (dossier de Siril sous Linux) puis dans
    ~/.local/share/kstars ;
  - soit tu cliques sur « ⬇ Gaia » dans la fenêtre « Astrométrie » : le
    catalogue astrométrique (≈ 1,1 Go) est téléchargé dans le dossier affiché
    par la ligne « Catalogues » (reprise automatique après coupure, sha256
    vérifié) ;
  - soit tu déposes toi-même siril_cat_healpix8_astro.dat (ou .dat.bz2) dans
    ce dossier — le bouton 📂 en choisit un autre, et c'est mémorisé.

La ligne « Catalogues » dit à tout moment OÙ l'application cherche, si le
catalogue est présent, et combien de morceaux « spectres Gaia » (utiles à la
SPCC) sont là. Sans catalogue, l'astrométrie l'annonce clairement
(« DONNÉES MANQUANTES — … ») au lieu d'échouer en silence.

Autre possibilité : ASTAP (outil externe `astap_cli` + une base d'étoiles de
type G18/H18 pour chercher sans coordonnées) — AVAStack le détecte dans le
PATH et dans /usr/local/bin, /usr/bin, /opt/astap.

OUTILS EXTERNES (optionnel) : GRAXPERT, BLURXTERMINATOR
------------------------------------------------------
AVAStack sait lancer deux outils en ligne de commande : GraXpert (retrait
de gradient, et un débruitage par IA, lent) et le CLI rc-astro
(BlurXTerminator, netteté). Ils ne sont PAS fournis avec AVAStack : à
installer toi-même. L'application dit TOUJOURS où elle les a trouvés — une
ligne d'état sous chaque commande du cadre « Traitement externe (long) » :
    ✔ GraXpert : /chemin/trouvé        (vert)
    ⚠ GraXpert : exécutable introuvable…  (orange, avec le bouton « … »)

GraXpert sous Linux :
  1. télécharger l'archive « graxpert-linux-amd64.zip » depuis les Releases
     officielles (github.com/Steffenhir/GraXpert/releases) ;
  2. l'extraire où tu veux (par exemple ~/GraXpert-linux-amd64/) ;
  3. la rendre exécutable — OBLIGATOIRE :
         chmod u+x ~/GraXpert-linux-amd64/GraXpert-linux
     sous Linux le binaire s'appelle « GraXpert-linux » (il n'y a ni
     graxpert.exe ni paquet .deb) ;
  4. relancer AVAStack : la ligne d'état doit afficher « ✔ GraXpert : … ».

Détection automatique (dans cet ordre) : le chemin noté par SIRIL (clé
graxpert_path de ~/.config/siril/configX.Y.ini) → la variable
AVASTACK_GRAXPERT → le PATH → ~/.local, /usr/local, /opt, ~/Applications
et ton dossier personnel (dossiers ou fichiers commençant par « GraXpert » :
archive décompressée, AppImage). Si rien n'est trouvé, désigne l'exécutable
une fois pour toutes avec le bouton « … » : le chemin est mémorisé.

BlurXTerminator : l'installeur rc-astro pose « rc-astro » dans le PATH ;
sinon, même bouton « … » (ou variable AVASTACK_RC_ASTRO).

Aucun traitement externe n'est lancé sans son outil : l'application le dit
AVANT de commencer (message clair) au lieu d'échouer en cours de route.


BANCS CAMÉRA INSTALLÉS (sous-dossier bancs/cameras)
-----------------------------------------------
Seuls les bancs du THÈME CAMÉRA sont installés avec l'application :
  - bancs/cameras/_diag_camera_qhy.py, _diag_camera_playerone.py,
    _diag_camera_svbony.py, _diag_camera_touptek.py : diagnostic d'une caméra
    HORS de l'application (détection, contrôles SDK, TEC, flux) ;
  - bancs/cameras/_diag_qhy_sdk.py : le SDK QHYCCD seul, sans caméra ;
  - les bancs de régression de la couche caméra (_test_camera_*.py,
    _test_capacites*.py, _test_tec*.py, _test_qhy_camera.py…) : ils tournent
    SANS matériel (SDK factices).

Lancement, depuis CE dossier (chaque banc trouve la racine du programme) :
    ./venv/bin/python bancs/cameras/_diag_camera_qhy.py

Les autres bancs (solveur, couleurs, chromatisme, sauvegardes, gradient…) sont
des outils de DÉVELOPPEMENT : ils ne sont pas installés, ils vivent dans le
dépôt, sous bancs/, et se lancent depuis la racine du dépôt.

DÉPENDANCES SYSTÈME (si l'application refuse de démarrer)
--------------------------------------------------------
AVAStack a besoin de Tkinter (paquet SYSTÈME `python3-tk` : il n'existe pas
sur pip) et, pour OpenCV, de bibliothèques graphiques. Si le lancement
échoue, teste :

    ./venv/bin/python -c "import tkinter"
    ./venv/bin/python -c "import cv2"

et installe ce qui manque (avec les droits administrateur) :

    Debian / Ubuntu / Linux Mint :
        sudo apt install python3 python3-venv python3-tk libgl1 libglib2.0-0 libusb-1.0-0
    Fedora :
        sudo dnf install python3 python3-tkinter mesa-libGL glib2 libusb1
    Arch / Manjaro :
        sudo pacman -S python python-pip tk libgl libusb

CONFIGURATION ET DONNÉES
------------------------
Réglages de l'application :
    ~/.config/AVAStack/config.json
Les images que tu enregistres vont où TU choisis (aucun dossier imposé).

Lancement :
    avastack            (si ~/.local/bin est dans ton PATH)
    ./lancer_avastack.sh (directement depuis le dossier d'installation)
    ou l'entrée « AVAStack » du menu Applications.

MISE À JOUR
-----------
Ferme AVAStack, extrais le nouveau paquet et relance `install_avastack.sh` :
le venv et tes réglages sont réutilisés (l'ancienne installation reste
consultable en cas de régression — les paquets sont nommés avec leur
version).

DÉSINSTALLATION
---------------
Depuis le dossier extrait du paquet (ou depuis le dépôt) :

    bash installer/install_avastack.sh --desinstaller           (garde les réglages)
    bash installer/install_avastack.sh --desinstaller --purger  (supprime aussi
                                                                 les réglages)

Si tu avais installé dans un autre dossier (`--prefix`), répète ce `--prefix`
à la désinstallation. L'aide complète : `bash
installer/install_avastack.sh --aide`.
